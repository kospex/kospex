# kweb: empty scopes and unknown ids (#206, #367, #368)

## Overview

Two related failures on kweb pages that take a repository, organisation or
server id:

1. **`/tenure/` returned HTTP 500 when its scope had no commits** (#206, fixed
   in #367). That happened for an unknown id, for a known repo with no commits,
   and for the unscoped `/tenure/` on a fresh install, before anything was
   synced.
2. **Nearly every other id page rendered an empty page with HTTP 200 for an id
   that isn't in the database** (the related gap in #206, fixed in #368). That
   looks the same as a real scope with no data. An unknown id is most likely a
   typo or a stale link. On a one-repo database, 46 of 49 (route, id kind)
   combinations behaved this way. Only `/tenure/` (after #367) and `/collab/`
   returned 404.

Unknown ids now get a 404 that names the id, for example
`No repository with ID 'github.com~acme~nope' in the kospex database. Check it for a typo.`
A known scope with no commits on `/tenure/` renders with a "No commits synced …"
message.

## Files changed

- `src/kospex_query.py`
  - `get_activity_stats()` guards on the `commits` count, not on the row. It is
    a pure aggregate, so SQL returns one row even when nothing matches
    (`commits = 0`, NULL first and last commit). It now returns
    `days_active = 0` and `years_active = 0` instead of passing `None` to the
    date parser.
  - New `scope_exists(params)`: True if the `repo_id`, `org_key` or `server` has
    a row in `repos`. The all-repositories scope and a developer
    (`author_email`) scope always count as existing. A malformed `org_key`
    returns False rather than raising from `where_org_key`.
- `src/kweb2.py`
  - New `_SCOPE_KINDS` (scope key → the word the user sees) and
    `_require_known_scope(params, id)`, which raises the 404 through the
    existing `404.html` handler. It does nothing when there's no id.
  - Called in 24 HTML routes. Repo, org or server id: `/summary/`,
    `/summary2/`, `/metadata/repos/`, `/orphans/`, `/bubble/`, `/treemap/`,
    `/osi/`, `/repos/`, `/landscape/`, `/developers/`, `/tenure/`. Repo id:
    `/developers/active/`, `/collab/graph/`, `/file-collab/`, `/repo/`,
    `/key-person/`, `/commits/`, `/history/`, `/commit/`, `/hotspots/`,
    `/files/repo/`. Server: `/orgs/{server}`. Org: `/org/`, `/graph/`.
  - `/commit/{repo_id}/{hash}` also returns 404 for a commit hash that isn't in
    the repository.
  - `/tenure/` passes `no_commits_message` to the template.
- `src/templates/tenure.html`: shows `no_commits_message` above the basic
  statistics.
- `tests/test_tenure_empty_scope.py` (#367) and `tests/test_unknown_id_404.py`
  (#368).
- `CHANGELOG.md`: two entries under Unreleased → Fixed.

## Deliberately unchanged

- **`/dependencies/{id}`** already shows a "Repository not synced" empty state
  with the commands to run, which is more useful than a 404.
- **`/collab/{repo_id}`** already returned 404 (#43).
- **JSON routes** (`/api/collab/graph/`, `/org-graph/`): the 404 handler renders
  HTML, which is wrong for a JSON client.
- **Developer ids** (`/developer/{id}`, base64 ids, `?author_email=`): what
  "unknown developer" means is a separate decision.
- **Scope ids passed as query parameters** (`/repos/?org_key=` and others):
  the check only sees the path id. Tracked in #369, with the plan in
  `changes/202611-unknown-scope-404-guard.md`.

## Implementation notes

- **Handler tests call the handler directly** with a hand-built
  `starlette.requests.Request`, not through `TestClient`. starlette's
  TestClient needs `httpx2`, which isn't installed locally, so TestClient
  suites skip there. KospexQuery is pointed at the test DB with
  `monkeypatch.setattr(kweb2, "KospexQuery", lambda *a, **k: KospexQuery(kospex_db=db))`.
- **The route survey** (status codes for known and unknown ids across every id
  route) used `TestClient` in an `ubuntu:26.04` container, with
  `base_url="http://localhost"`. The default `testserver` host makes every
  route return 400.
- **The web suite only passed before because it ran against a populated
  database.** `test_html_endpoints_main_pages[/tenure/]` failed on a fresh one.
  The fix was verified with a live kweb on an empty database (full suite: 0
  failed). It was also checked for false 404s against a populated database:
  every `repo_id` (including `~~` ids), every `org_key` as `orgs()` links it,
  and every server pass `scope_exists()`, directly and after
  `get_id_params()`.
- On `/commits/`, the handler's `repo_id` argument binds from the query string
  when the path has none, so `/commits/?repo_id=<unknown>` is already covered.
