# Contributing to kospex

Bug reports, issues and pull requests are welcome via
[GitHub issues](https://github.com/kospex/kospex/issues).

## Before you open a pull request

**Claim the issue first.** Comment on the issue saying you'd like to work on it,
and wait for a maintainer to confirm before you open a PR. Many issues are already
in progress, or describe a fix the maintainers intend to make themselves. A PR for
an issue nobody has claimed may be closed without review, even if it is correct.

If there is no issue for the change you want to make, open one first.

**Disclose AI-generated work.** If an AI tool wrote a substantial part of the code,
tests or PR description, say so in the PR and name the tool. AI-assisted PRs are
welcome; we only need to know, so we review them with that in mind.

## Development setup

See [Contributing in the README](README.md#contributing) to install kospex in
editable mode and run the tests.

In the PR, say what you ran: the full `pytest` suite, not only the new tests, and
the passed / skipped counts it reported.
